# Docker Basic API

A basic deployable Node.js + Express API packaged with Docker.


live api : https://docker-basic-api-latest.onrender.com/ 

# check GET https://docker-basic-api-latest.onrender.com/api/health

This project is used to understand the complete Docker deployment flow:

```text
Source Code
   ↓
Dockerfile
   ↓
Docker Image
   ↓
Docker Container
   ↓
Docker Hub
   ↓
Render / AWS EC2
```

## 4. Express Server

Create:

```text
src/server.js
```

```javascript
import express from "express";
import dotenv from "dotenv";
import mongoose from "mongoose";

dotenv.config();

const app = express();

app.use(express.json());

const PORT = process.env.PORT || 5000;

const connectDB = async () => {
  try {
    await mongoose.connect(process.env.MONGO_URI);
    console.log("MongoDB Atlas connected");
  } catch (error) {
    console.error("MongoDB connection failed:", error.message);
    process.exit(1);
  }
};

app.get("/", (req, res) => {
  return res.status(200).json({
    success: true,
    message: "Docker API is running",
  });
});

app.get("/api/health", (req, res) => {
  return res.status(200).json({
    success: true,
    api: "healthy",
    database:
      mongoose.connection.readyState === 1
        ? "connected"
        : "disconnected",
    environment: process.env.NODE_ENV,
    timestamp: new Date().toISOString(),
  });
});

const startServer = async () => {
  await connectDB();

  app.listen(PORT, "0.0.0.0", () => {
    console.log(`Server running on port ${PORT}`);
  });
};

startServer();
```

### Why `0.0.0.0`?

```javascript
app.listen(PORT, "0.0.0.0");
```

Inside Docker, the application should listen on all network interfaces.

Using only `localhost` may make the application inaccessible from outside the container.

## 6. Environment Variables

Create:

```text
.env
```

```env
PORT=5000
NODE_ENV=development
MONGO_URI=mongodb+srv://USERNAME:PASSWORD@cluster.mongodb.net/docker_api
```

Important:

* Never commit `.env` to GitHub.
* Never add secrets directly inside the Dockerfile.
* Never hardcode MongoDB URLs or API keys in source code.
* Use different environment variables for local and production environments.

If the MongoDB password contains special characters, URL-encode them.

```text
@  → %40
#  → %23
/  → %2F
%  → %25
```

# Docker Setup

## 8. Dockerfile

Create a file named exactly:

```text
Dockerfile
```

Do not use:

```text
Dockerfile.txt
```

Dockerfile content:

```dockerfile
FROM node:22-alpine

WORKDIR /app

COPY package*.json ./

RUN npm ci --omit=dev

COPY . .

ENV NODE_ENV=production

EXPOSE 5000

CMD ["npm", "start"]
```

### Dockerfile Explanation

```dockerfile
FROM node:22-alpine
```

Uses Node.js 22 on a lightweight Alpine Linux image.

```dockerfile
WORKDIR /app
```

Sets `/app` as the working directory inside the container.

```dockerfile
COPY package*.json ./
```

Copies `package.json` and `package-lock.json` first.

```dockerfile
RUN npm ci --omit=dev
```

Installs exact locked dependencies without development dependencies.

```dockerfile
COPY . .
```

Copies the remaining project files into the image.

```dockerfile
ENV NODE_ENV=production
```

Sets the default Node environment inside the image.

Sensitive values should not be placed here.

```dockerfile
EXPOSE 5000
```

Documents that the application uses port `5000`.

It does not automatically publish the port.

```dockerfile
CMD ["npm", "start"]
```

Runs when a container starts from this image.

## 9. `.dockerignore`

Create:

```text
.dockerignore
```

```dockerignore
node_modules
npm-debug.log
.git
.gitignore
.env
README.md
coverage
.vscode
```

### Why `.dockerignore`?

It prevents Docker from copying:

* local `node_modules`
* Git history
* editor settings
* environment secrets
* logs
* test coverage files

This keeps the image smaller and safer.

## 12. Run the Container

Windows CMD:

```cmd
docker run -d --name docker-api-container -p 5000:5000 --env-file .env docker-basic-api
```

Linux multiline version:

```bash
docker run -d \
  --name docker-api-container \
  -p 5000:5000 \
  --env-file .env \
  docker-basic-api
```

Meaning:

| Option             | Purpose                                    |
| ------------------ | ------------------------------------------ |
| `-d`               | Runs the container in the background       |
| `--name`           | Assigns a readable container name          |
| `-p 5000:5000`     | Maps host port 5000 to container port 5000 |
| `--env-file .env`  | Passes environment variables at runtime    |
| `docker-basic-api` | Image used to create the container         |

Port format:

```text
HOST_PORT:CONTAINER_PORT
```

# Updating the Application

## 17. Update Local Container After Code Changes

Docker images do not update automatically when source code changes.

Remove old container:

```bash
docker rm -f docker-api-container
```

Rebuild image:

```bash
docker build -t docker-basic-api .
```

Run new container:

```bash
docker run -d --name docker-api-container -p 5000:5000 --env-file .env docker-basic-api
```

Update flow:

```text
Code Change
   ↓
Remove Old Container
   ↓
Build New Image
   ↓
Run New Container
```

## 19. Tag the Image

Docker Hub image naming format:

```text
DOCKERHUB_USERNAME/REPOSITORY_NAME:TAG
```

Command:

```bash
docker tag docker-basic-api:latest testdevelopment332718/docker-basic-api:latest
```

Check:

```bash
docker images
```

Both image names can point to the same image ID:

```text
docker-basic-api
testdevelopment332718/docker-basic-api
```

Tagging does not create a second full image copy. It creates another reference to the same image.

---

## 20. Push Image to Docker Hub

```bash
docker push testdevelopment332718/docker-basic-api:latest
```

Docker Hub now stores the image.

Deployment platforms can pull and run it without needing the source code.

```text
Local Docker Image
   ↓ docker push
Docker Hub Registry
   ↓ docker pull
Server / Cloud Platform
```

---

## 21. Recommended Version Tags

Instead of using only `latest`, use release versions:

```bash
docker build -t testdevelopment332718/docker-basic-api:v1 .
docker push testdevelopment332718/docker-basic-api:v1
```

Next version:

```bash
docker build -t testdevelopment332718/docker-basic-api:v2 .
docker push testdevelopment332718/docker-basic-api:v2
```

Also update `latest` when required:

```bash
docker tag testdevelopment332718/docker-basic-api:v2 testdevelopment332718/docker-basic-api:latest

docker push testdevelopment332718/docker-basic-api:v2
docker push testdevelopment332718/docker-basic-api:latest
```

Benefits:

```text
v1       Old stable release
v2       New release
latest   Current release
```

Version tags make rollback easier.

# Environment Variable Flow

## 22. Local Environment Flow

Local run command:

```bash
docker run --env-file .env docker-basic-api
```

Flow:

```text
Local .env
   ↓ --env-file
Container Runtime Environment
   ↓
process.env.MONGO_URI
   ↓
MongoDB Connection
```

The `.env` file is not copied into the image because it is listed in `.dockerignore`.

---

## 23. Production Environment Flow

On Render or AWS, production environment variables are supplied separately.

```text
Cloud Environment Configuration
   ↓
Running Container
   ↓
process.env
   ↓
Application
```

The same Docker image can run in different environments:

```text
Same Image + Local Env       = Local Application
Same Image + Render Env      = Render Application
Same Image + AWS Env         = AWS Application
```

Environment variables are runtime configuration, not image source code.

# AWS EC2 Deployment Summary

## 26. Docker-Based AWS Flow

```text
Local Source Code
   ↓
docker build
   ↓
docker push
   ↓
Docker Hub
   ↓
AWS EC2 docker pull
   ↓
docker run
```

Important:

* Images are pushed to Docker Hub.
* Images are pulled on EC2.
* Docker containers normally do not require PM2.
* Docker manages the application process.
* `--restart unless-stopped` provides automatic restart behavior.

# Docker vs PM2

## 31. When to Use PM2

PM2 is useful when a Node.js application is deployed directly:

```text
EC2
→ git clone
→ npm install
→ pm2 start src/server.js
```

## 32. When Using Docker

Docker flow:

```text
EC2
→ docker pull
→ docker run
```

In this setup, PM2 is generally unnecessary.

Use:

```bash
--restart unless-stopped
```

# Final Docker System Understanding

```text
Dockerfile
   Defines how the image is built

Docker Image
   Read-only packaged application

Docker Container
   Running instance of an image

Docker Hub
   Remote registry used to store images

Environment Variables
   Runtime configuration and secrets

Port Mapping
   Connects host traffic to the container

Docker Pull
   Downloads an image from a registry

Docker Push
   Uploads an image to a registry

Docker Run
   Creates and starts a container from an image
```
